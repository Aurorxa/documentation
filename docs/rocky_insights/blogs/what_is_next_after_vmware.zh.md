自 Broadcom 收购 VMware 以来，虚拟化行业经历了重大变化，特别是在许可定价方面。Broadcom 的新定价政策（这不是一个评判）导致了显著的成本增加，尤其是对使用 VMware 的中小企业而言。因此，许多组织被促使重新考虑其技术选择。

这些价格调整推动了受影响的公司去探索替代方案，尤其是开源解决方案。

本文旨在展示基于开源技术的虚拟化解决方案的可行性、优势和性能，为 VMware 提供一个可行的替代方案。

我想澄清一点，我本人以及文档团队与下面将要提到的解决方案均无任何关联。

## 期望的功能特性

在开始讨论市场上可用的解决方案之前，让我们花点时间谈谈我们可以从虚拟化解决方案中期望的功能特性。

在与该主题相关的多次讨论中，一个经常被提及但最初常被忽视的关键点就是备份。选择解决方案时的关键因素将是：这个解决方案是否拥有健壮的备份解决方案？我甚至会具体指出，如果你已经在使用像 Veeam Backup 这样的解决方案，并且不想更换（由于成本、已掌握的技能或安全原因），我当前的软件是否支持它？

其他需要考虑的功能特性包括：

- 备份和恢复、VM 快照
- 容器化和/或集成的 Kubernetes
- 托管数据库
- IAAS：VPC、网络虚拟化和自助服务门户
- DevOps 集成成熟度（Terraform、Ansible）——API
- S3 对象存储（Ceph...）
- 集成 VPN（尤其是站点到站点，site-to-site）
- 安全组（Security Groups，虚拟防火墙）
- IPAM、托管 DHCP、负载均衡、SNAT
- 监控

一些解决方案还提供：

- 从 VMware 的集成迁移

## 选择 Hypervisor（虚拟化管理程序）

在深入了解现有解决方案之前，让我们看看可用的 hypervisor 选择：

- **ESXi**，VMware 的 hypervisor。如果考虑它，很可能是为了简化迁移。
- **KVM (QEMU/libvirt)**：集成在内核中，这是功能方面最先进的开源解决方案之一，被广泛使用。
- **Xen (XCP-ng)**：Citrix 的继任者。它是一个健壮的、较老的 hypervisor，可能仍有一些技术债务，但似乎正在积极开发中，很可能很快赶上。
- **AHV (Nutanix)**：这里我们正在远离开源解决方案，但我们稍后会讨论 Nutanix。
- **Hyper-V**：也值得一提，因为虽然是专有的，但如果 Microsoft 的定价低于 VMware 的产品，许多小企业可能会选择 Microsoft。

在你可以从 hypervisor 期望的功能特性中，你可能想要验证：

- 向客户机（guests）热添加 CPU 和 RAM
- 向客户机热添加或调整磁盘大小
- 集群内或跨集群的在线迁移（live migration）
- 在线存储迁移

在这一点上，比较 hypervisor 是棘手的，因为大多数通常都包含所有这些功能。选择实际上取决于你选择的 manager（管理器）类型。

## 选择 Manager（管理器）

现在我们进入问题的核心：选择你梦想中的管理器。谁将是最大的赢家，谁是你信赖的 vSphere 的理想替代品？那个能在最合适的 hypervisor 上无缝管理你的客户机的工具？

### 功能特性

先来谈谈这些解决方案的功能特性，这将帮助你缩小选项范围并设置 POC 来协助最终选择。

一个管理器应提供：

- 集群管理：高可用（High Availability，HA）、节点维护等。
- 自助服务门户：欢迎来到现代私有云和基础设施即服务（Infrastructure as a Service）的世界
- 网络虚拟化（SDN）、VPC
- API 管理
- 对 DevOps 工具（Terraform、Ansible、Puppet 等）的支持
- 跨集群迁移

### 现有解决方案

在本节中，我不会讨论像 Hyper-V 或 Nutanix 这样的专有解决方案。我只提一下 Nutanix 提供了许多与 VMware 竞争的功能特性，并提供响应迅速的专业支持。与我在下面将介绍的解决方案的支持相比，它似乎仍然是一个更昂贵的解决方案，但价格比较留给你自己去做。

在我看来，要替代像 vSphere 这样的东西，最先进的解决方案是 **OpenStack**。受到许多供应商的支持，它是众多公有云的基础。但它也是实施起来最复杂的。如果你没有一个拥有时间投入的熟练 Linux 工程团队，请忘记 OpenStack。但是，如果你能投入这些时间，它就是适合你的解决方案。可以考虑查看像 **Virtuozzo** 这样的衍生解决方案以获得支持，或者来自 RedHat 和 Suse 等供应商的解决方案。

既然我首先提到了 **OpenStack**，我接下来必须继续谈论我长期偏爱的那个：Apache 基金会著名的顶级项目（确实如此），**CloudStack**。它具有与 OpenStack 相似的功能特性，提供了设置私有云门户所需的一切，包括 VPC 支持、网络虚拟化、负载均衡，甚至 **Kubernetes** 集群，全部在一个设计精良的自助服务门户中。它以 Java 应用的形式作为 rpm 或 deb 软件包提供，安装简单。最复杂的部分是在主机上配置虚拟交换机（支持 RockyLinux），但没有什么是不可能的。主机可以是 KVM、Xen、Hyper-V 或 ESXi，最近还支持了 Proxmox。正如我提到的，CloudStack 是少数几种通过 UI 提供从 vSphere 直接迁移客户机的解决方案之一。在 CloudStack 背后，有一个活跃的参与者 ShapeBlue 提供企业支持。在可扩展性方面，CloudStack 存在超过 35,000 台主机的实例，表明其具有良好的可扩展性。

接下来，我要提到 Proxmox，这是在此领域很可能获得最大市场份额的开源解决方案。基于 Debian（这里没有 RockyLinux ^^），我必须承认，在阅读了其编写精良的管理指南后，我对其功能特性印象深刻（IPAM、网络虚拟化、存储管理、容器支持，尤其是 Ceph 存储集成）。Proxmox 提供了集成的备份解决方案，并可选外部备份，以及一个新的数据中心管理解决方案（用于管理多个 Proxmox 集群）。如果你不需要像 CloudStack 那样的自助服务门户，专注于超融合模型（存储分布在主机上，而不是专用的 SAN/NAS），并且你的范围是几百个客户机，那么 Proxmox 很可能是正确的选择。

最后，我必须提到 Vates 和 XCP-ng，基于 Xen hypervisor 和 Xen-Orchestra Web 管理界面。在我看来，这些是需要关注的解决方案，因为它们建立在坚实的基础上并正在积极开发中（Vates 由一家法国公司开发，这充分说明了产品的质量！）。但请注意，在 Vates 中，你需要花费更多才能获得超融合存储（XOSTOR）或备份解决方案（XO Proxy）。

### 成本控制

鉴于本文的主题围绕 Broadcom 许可变更导致的成本增加展开，如果我不讨论与更换解决方案相关的财务方面，将是我的疏忽。

除了你可能希望在商业模式中订阅的支持费用之外，还必须考虑总拥有成本（Total Cost of Ownership，TCO），其中包括：

- 支持费用，
- 维护费用，
- 更新费用，
- 培训团队以及解决方案集成所需的时间，
- 迁移所花费的时间。

### 支持和社区

最后一个需要考虑的、通常是决定性的因素是公司和活跃社区所提供的支持。能够获得响应迅速的支持团队令人安心，能够依赖强大的社区获取建议和故障排除也同样重要。然而，值得注意的是，缺乏社区活动或糟糕的支持可能是一个重大缺陷。

## 结论

这篇简短的文章让我得以介绍市场上可用的主要解决方案，正如你所见，做出选择并不容易。这完全取决于你团队管理该工具的能力、你的备份解决方案、你所需的功能特性、你对 DevOps 工具和云原生方法的成熟度，以及要管理的客户机数量。

虽然我长期偏爱 CloudStack，但这个 Apache 项目仍然相对默默无闻（Apache 不像其他供应商那样推广它的项目），我强烈鼓励你在做出选择时考虑它。Proxmox 和 Vates 对于小企业乃至更大的需求来说也是优秀的解决方案，直到你迁移到基于 OpenStack（或 OpenShift）的解决方案。

希望这个快速概览能帮助你在寻找 VMware 替代方案的过程中节省时间。
