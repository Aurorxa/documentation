# 主动语态：通往简洁清晰沟通之路

## 主动语态与被动语态

如今关于在文档中使用主动语态存在巨大争议。这本不应有争议。原因是使用主动语态有助于创建直接且清晰的文档。我最近读了一篇社交媒体的帖子，其中质疑了这一事实。对话的要旨是：*"被动语态在文档中似乎没那么糟糕，我应该在意吗？"* 我可以向你保证，这**确实**重要，你**应该**在意。被动语态常常模糊且不清晰。被动语态可能导致技术写作中的混淆，尤其是在受众各异以及需要进行翻译的情况下。我们在 Rocky Linux 文档中的目标是创作优秀的文档，而优秀的文档不包括使用被动语态。请审视我们"风格指南"中的这一条：

> 用尽可能少的词表达你的意思。

主动语态迫使你做到这一点。以下是被动语态指令的示例：

对于我们的 Web 平台，必须使用以下命令安装 Apache：`sudo dnf install httpd`

而以下是主动语态的等价表达：

对于你的 Web 平台，使用以下命令安装 Apache：`sudo dnf install httpd`

这个例子中有几点值得注意。被动语态短语有 11 个词，而主动语态有 9 个。主动语态短语指示用户去"安装"Apache，而不是告诉用户它"必须被安装"。然而，在这两个例子中，指令——最重要的元素——都隐藏在句子主体中。虽然 9 个词是一种改进，但我们还可以做得更好。如果你记得"用尽可能少的词表达你的意思"这条规则，那么考虑以下写法：

安装 Apache，使用：`sudo dnf install httpd`

同样，我们使用了主动语态，但现在只用 3 个词而不是 9 个（或 11 个）。此外，我们的指令再清晰不过了。它简洁而直接。这对翻译和文档结构都有影响。翻译 3 个词对我们的译者来说更省力。3 个词的指令对读者来说一目了然。这从各方面看都是一种胜利。

在追求清晰指令时，将简化与主动语态结合有助于实现你的目标。

## 识别被动语态

当我在 2021 年开始为 Rocky Linux 编写文档时，我起步于一批在做网络管理员时写的文档。我的文档中充满了被动语态的表达，但在当时，我并不能轻易地识别它们。直到 2023 年末，我开始用于创建和编辑文档的编辑器（基于 [Neovim](https://neovim.io/) 的编辑器，搭配 [Vale](https://vale.sh/)）开始高亮显示被动语态短语。训练我的眼睛一眼"看到"被动语态短语是困难的。现在也并不总是容易发现的。以下是一些需要留意的事项，以帮助识别被动语态：

* 以或包含 'we'（我们）或 'our'（我们的）开头的指令

    这些几乎总是导致首先间接的表达，并且常常包含被动语态。在编写指令时使用 'you'（你）或 'your'（你的）。

* 注意以下动词：'was'、'were'、'are'、'been'、'be' 等，后跟通常（但并非总是）以 "ed" 结尾的过去分词短语。示例：

    * "was created"（被创建）
    * "were backed up"（被备份）
    * "are manipulated"（被操控）
    * "been restored"（被恢复）
    * "be installed"（被安装）
    * "is hidden"（被隐藏）

    以上每个都是被动语态的例子。

* 注意那些指令**不是**第一个最重要的元素（主语）的句子。

你可以训练自己的眼睛在校对时看到这些，但如果你坚持简化指令的目标，你会发现消除被动语态并不需要太多努力。使用支持 Vale 集成的编辑器仍然**非常**有帮助。

## 结论

在技术写作中使用主动语态有助于确保简洁清晰的指令。此外，进一步简化你的写作可以增强可读性、可理解性，并有助于减轻翻译工作。记住："用尽可能少的词表达你的意思。"
