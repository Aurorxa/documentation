## 准备工作就绪

现在你已经从头到尾阅读了这本管理员指南，可以无所畏惧地管理 Linux 服务器了。

在这本书中，你了解了众多高级命令和技巧。我们选择将其中一部分汇集于此，并附上一些我们自己最喜欢的小贴士作为额外内容。

这些正是区分普通 linux 管理员与 Linux 管理员（大写）的关键所在。

!!! note

    下面的技巧没有一个是必不可少的，没有它们你也能很好地管理服务器。它们只是些细微的优化，日积月累，能让命令行上的日常操作更加愉快。

## 选项结束标记 `--`

`--` 标志着命令选项的结束。这意味着之后的所有内容都是参数，即使以短划线开头也不例外。在以下命令中，`--hard` 不是一个长选项，而是要创建的目录名：

```bash
mkdir -p -- --hard
```

当需要处理文件名以短划线开头（如 `-file`）的文件时，这个技巧很有用，因为否则命令会将其误认为选项。

## 使用 `newgrp` 切换主组

`newgrp` 命令启动一个子 shell，在这个子 shell 中，你的主组将变为你的某个次要组。例如，如果你属于 `support` 组：

```bash
newgrp support
```

会启动一个子 shell，其中你的有效 GID 是 `support` 组的 GID。要退出并返回默认 GID，只需退出子 shell（++ctrl+d++ 或 `exit`）。这个命令虽然不太为人所知，但在让你创建的文件属于正确的组方面非常方便。

## 使用 `gpasswd` 为组设置密码

`gpasswd` 命令允许为组分配密码。这有什么用处呢？知道组密码的人可以通过 `newgrp` 切换到该组，即使不是该组的成员。`gpasswd` 还允许指定组管理员（`gpasswd -A`），管理员可以添加或删除成员而无需 root 权限。

## 永远不要在目录树上运行 `chmod -R 644`

一个常见的管理错误是运行：

```bash
chmod -R 644 /target
```

这会移除所有子目录的执行（`x`）权限，导致任何人都无法进入这些目录。更好的做法是只用 `find` 针对文件操作：

```bash
find /target -type f -exec chmod 644 '{}' \;
```

!!! warning

    末尾的 `\;` 是必须的。你也可以使用 `+` 代替，这会将调用批量合并，运行更快：

    ```bash
    find /target -type f -exec chmod 644 '{}' +
    ```

更优雅的方式是使用大写的 `X`，它只会设置目录的 execute 位（以及已经拥有 execute 位的文件），一条命令即可：

```bash
chmod -R u=rwX,go=rX /target
```

## `tar` 使用键而非选项

`tar` 命令历史上使用的是键（key）而非选项（option）。具体来说，`tar xvf` 可以正常工作，而 `tar -xvf` 在旧系统上不一定能工作。同样，过去你需要指定解压格式（bzip2 用 `j`，gzip 用 `z`），而现代版本会自动检测。

## `/etc/fstab` 行末尾的两个整数

在 `/etc/fstab` 的每一行末尾，有两个整数，通常是 `0 0`。第一个指示是否在备份中（通过 `dump` 工具）包含该文件系统。第二个设置 `fsck` 在引导时检查文件系统的顺序（在检查文件系统可能耗时很长的年代）：

| 值   | 含义                              |
| ----- | ----------------------------------- |
| 0     | 引导时不检查                       |
| 1     | 优先检查（保留给 `/`）              |
| 2     | 之后检查（其他分区）                |

## 在 vim 中使用 `:x` 保存并退出

在 vim 中，`:x` 只需两次按键即可保存并退出，而 `:wq` 需要三次。有一个细微差别：与 `:wq` 不同，`:x` 仅在文件有修改时才写入，因此不会无谓地更新修改时间，这对于 `make` 或文件监视器来说很重要。在普通模式下，++shift+z++ ++shift+z++ 的功能完全相同。

## 管道只传递 `stdout`

`|` 仅将一个命令的 `stdout` 连接到下一个命令的 `stdin`。`stderr` 流默认不会通过管道。对于像 `ssh -V` 这样的命令来说，这可能会带来不便，因为它们将版本信息输出到 `stderr` 通道（通道 2）。

要让 `stderr` 通过管道，将通道 2 重定向到通道 1：

```bash
ssh -V 2>&1 | cut -d',' -f1
```

!!! tip

    注意重定向的顺序。输出重定向必须放在 `stderr` 重定向**之前**，否则结果将不如预期。以下写法**不会**按预期工作：

    ```bash
    ssh -V 2>&1 1>test.txt
    ```

    应该这样写：

    ```bash
    ssh -V 1>test.txt 2>&1
    ```

`java -version`（单短划线；注意 Java 9 引入的双短划线 `java --version` 会输出到 `stdout`）或 `python2 --version` 过去也是如此。

## 利用花括号展开快速备份

无需重新输入文件名，让 shell 将 `{,.bak}` 展开为两个字符串（空和 `.bak`）：

```bash
cp file.conf{,.bak}
```

这会创建 `file.conf.bak`。同样的原理还可以一次性创建整个目录树：

```bash
mkdir -p project/{src,bin,doc}
```

## 获取最后一个参数的历史快捷方式

几个快捷方式可以帮你省去重新输入最后一个参数的麻烦。`!$` 重新注入上一条命令的最后一个参数：

```bash
mkdir -p /some/slightly/long/path && cd !$
```

++alt+"."++ 以交互方式执行相同操作，反复按下则遍历参数历史。++esc++ 然后 ++"_"++ 产生相同的 `readline` 函数（`yank-last-arg`），++esc++ 充当 Meta 键。至于著名的：

```bash
sudo !!
```

它会以 `sudo` 为前缀重新运行上一条命令，这是忘了加 `sudo` 时的条件反射。

## 使用 `cd -` 跳回

`cd -` 将带你回到上一个目录，方便在两个文件夹之间来回切换。而单独的 `cd`（不带参数）将带你回到主目录。

## `[` 实际上是一个真正的程序

你在 `if` 中写的 `[ ... ]` 测试并非神奇的 shell 语法：`[` 是一个完整的命令（`/usr/bin/[`），就像 `true` 和 `false` 也是真正的二进制文件一样。

## 使用 setgid 位实现组继承

在目录上设置 setgid 位会强制组继承：

```bash
chmod g+s /share
```

此后，在 `/share` 中创建的任何文件都属于该目录的组，而非创建者的主组。这是团队共享目录的关键技巧，与上面的 `newgrp` 和 `gpasswd` 技巧完美互补。

## 在编辑器中编辑当前命令行

++ctrl+x++ ++ctrl+e++ 会在编辑器中打开当前正在输入的命令。对于失控的长命令行来说，这是一根救命稻草：shell 在 `$EDITOR` 中打开当前行，并在你关闭文件时执行它。这比用方向键编辑三行的命令要舒适得多。

## 使用 `chattr +i` 将文件设为不可变

```bash
chattr +i /etc/resolv.conf
```

你将无法修改或删除该文件，即使是 root 也不行，直到移除该属性（`chattr -i`）。这是防止误删（`rm`）或防止某个服务在每次重启时重写 `resolv.conf` 的完美保护措施。

## 使用 `xargs` 将列表转换为参数

`xargs` 命令将 `stdin` 接收到的列表转换为另一个命令的参数。使用 `-I{}` 占位符，可以为接收到的每一行构建一条命令：

```bash
ls *.log | xargs -I{} mv {} {}.old
```

你可以用 `-P` 来实现并行化（此处为同时执行 4 个任务）：

```bash
cat urls.txt | xargs -P4 -I{} curl -sO {}
```

对于包含空格的文件名，安全的组合是 `find -print0` 搭配 `xargs -0`，它们使用空字节（null byte）而非空格来分隔条目：

```bash
find /target -type f -print0 | xargs -0 -I{} cp {} /backup/
```

作为一个几乎没什么用的额外技巧，不带命令的 `xargs` 默认调用 `echo`，这使它成为了一个简陋的"修剪"工具：它会去除首尾空格并将多个连续空格合并为一个。
