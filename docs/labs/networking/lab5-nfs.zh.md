# 实验 5: 网络文件系统概述

!!! info

    在继续本实验之前，你需要准备好实验 3 中的文件，路径如下：`/shared/systems_administration_I/lab3-network_basics`。

    输入命令 `lab5-nfs`，启动一个名为 `lab5-nfs` 的 `tmux` 会话。更多信息请参见 [tmux helper scripts](../../../tools_scripts/lab_helpers.md)。

    在本实验中，你将研究配置和使用 NFS（Network File System）以及 NFS 挂载。

    !!! knowledge "知识要点"

        本实验将让你亲身体验 NFS 的使用。你将逐步完成在每个节点上创建导出目录的步骤。你还将看到如何配置基于 NFS 的共享目录或卷，使之能被其他节点访问、挂载和使用。

        在本实验结束时，你还将探索其他或相关的设置，并通过简短的练习挑战你的技能。

## 介绍

本实验旨在帮助你深入了解 NFS 服务器和 NFS 客户端的操作。你将学习 NFS，并通过创建实验室拓扑来获得实践经验。

### 先决条件

在开始实验之前，你需要做好以下准备：

* 你需要 3 台机器（或容器）满足以下最低要求：
    * CPU：2 个
    * 内存：2 GB
    * 存储：30 GB
    * Rocky Linux 9.x 操作系统
    * 每台机器安装两个额外的硬盘：第一个容量 4GB，第二个 2GB
* 管理员（"root"）或具有完整 sudo 访问权限的帐户
* 所有节点相互通信良好
* 一个名为 `NFS_SRV` 的节点，用于托管 NFS 服务器守护进程
* 一个名为 `NFS_SRV2` 的节点，也用于托管 NFS 服务器守护进程
* 一个名为 `NFS_CLIENT` 的节点，将作为我们的 NFS 客户端

## NFS 卷

你需要决定你想让哪些文件系统供远程客户端访问。在服务器上，通常通过所谓的导出来使文件系统可被访问。所谓"导出"，即管理员使本地卷上的整个或部分文件系统可被 NFS 客户端访问。然后，客户端将它们作为 NFS 挂载来挂载，与挂载任何其他标准的本地文件系统的方式类似。

服务器拥有 /etc/exports 文件来管理导出的文件系统。管理员可以在此文件中添加相应的条目，详情见下文。

### NFS 服务器设置

在本实验中，你将使用两台机器作为 NFS 服务器，即名为 `NFS_SRV` 和 `NFS_SVR2` 的节点。执行以下操作：

1. 在你的服务器上安装 NFS 软件包——默认由 `nfs-utils` 提供。
2. 在服务器上运行必要的 NFS 服务：
    * `rpcbind` 服务是 NFSv3 所必需的。NFSv2 和 NFSv3 使用 `rpcbind` 服务进行 RPC 注册。
    * 对于 NFSv4，你需要这两个服务。

    验证所有服务都已正确启动并启用。

    !!! question "问题"

        需要运行哪些必要的服务才能使 NFS 服务器正常工作？列出它们的名称。

3. 你现在可以为将作为 NFS 挂载呈现给客户端而创建的卷设置文件系统。

    * 配置 NFS 服务器上的两个额外磁盘。将第一个（4GB 的）格式化为 `ext4`，第二个（2GB 的）格式化为 `xfs`。
    * 创建两个挂载点：一个名为 `/nfs_share/ext4_vol`，另一个名为 `/nfs_share/xfs_vol`。
    * 按照你的意愿挂载文件系统，但设置方式是让它们永久挂载。提示：使用 `/etc/fstab` 文件。

    !!! question "问题"

        在服务器上，需要运行什么命令才能立即挂载 `/etc/fstab` 中的所有条目，而不必等到重启？

4. 接下来，在 `ext4` 和 `xfs` 文件系统上创建一些内容，以验证 NFS 设置的功能。在 `/nfs_share/ext4_vol` 目录下创建至少两个文件，并在 `/nfs_share/xfs_vol` 目录下创建两个目录。

    赋予这些文件和目录适当的权限，包括允许其他人读取和写入。

5. 通过在 `/etc/exports` 文件中添加条目来导出这些文件系统。
    在规划导出选项时，请注意以下几点：

    * 只在 `/etc/exports` 文件中添加允许从本地网络上的客户端进行读写访问的条目。
    * 选择一种安全的导出选项，确保挂载导出的客户端无法在卷上执行 `setuid` 程序，并且它们的 `root` 用户（用户在客户端上以 root 身份运行）在服务器上也不拥有 root 权限。
    * 注意，对 `/nfs_share/ext4` 导出使用 "sync"。（当服务器崩溃时,"sync"会降低服务器重启时丢失数据的可能性）。

    在 `/etc/exports` 文件中创建有效条目后，使用 `exportfs` 命令使导出生效。之后，在任何 NFS 客户端上，使用 `showmount` 命令检查服务器已导出的目录。

    !!! question "问题"

        如果要在主 NFS 服务器上添加仅允许来自本地网络的主机、具有读写权限、`root squashed` 且同步写入的条目，需要在 `/etc/exports` 中添加什么？

    !!! question "问题"

        如果在配置之前的某项更改后收到关于未知文件系统类型的错误，可以使用哪个命令来检查服务器上导出的卷列表？

### NFS 客户端设置

使用名为 `NFS_CLIENT` 的节点作为 NFS 客户端，执行以下操作：

1. 在 `NFS_CLIENT` 上安装必要的客户端软件包。
    * 使用 `showmount` 等命令查看 NFS 服务器导出的共享。
    * 为这两个共享在你的客户端上创建本地挂载点。

    !!! question "问题"

        哪个命令可以列出 `NFS_SRV` 服务器上可用的导出？

    * 手动挂载这些 NFS 共享。
    * 通过添加永久条目将 NFS 共享分别挂载到一个名为 `/mnt/nfs_test/` 的通用目录下的不同目录中。
    * 通过检查挂载表或 `/etc/mtab` 文件来确认挂载是否成功完成。

    !!! question "问题"

        挂载 NFS 共享的命令是什么？查看本机的 NFS 挂载。

    * 检查权限并尝试从客户端在 NFS 挂载目录中创建文件。

    !!! question "问题"

        为什么在 NFS 共享上创建文件时会遇到问题？

    * 访问 `/nfs_share/ext4` 的挂载点，检查你之前在 NFS 服务器上创建的文件是否可见。尝试修改至少其中一个文件。

    !!! question "问题"

        有哪些替代的图形化或命令行工具可以查看 NFS 服务器向客户端暴露的挂载点和权限？

    * 在挂载的共享上创建大量文件（如 30 个文件），然后使用正确的方式卸载其中一个共享。请检查客户端是否仍连接着另一个共享，且其中的文件仍然可用且完整。

        !!! tip

            如果卸载第一个共享后遇到任何问题，而你使用的是 NFSv3，请确保停止 `rpcbind`，然后再次运行挂载等。

    !!! question "问题"

        如何正确卸载 NFS 共享？可以使用哪些工具？
