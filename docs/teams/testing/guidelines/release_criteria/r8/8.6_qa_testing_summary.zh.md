## 范围

本文档将记录 Rocky Linux 8.6 版本所有 QA 与测试结果的摘要。它仅是成功和/或失败的记录。解决方案的讨论应在其他地方进行。

## 标准操作流程 (SOP)

- 所有条目请酌情包含 PASS、FAIL、NOTABUG、INVESTIGATE 或 UPSTREAM 标记。
- 请仅提供简短摘要。详细信息应记录到 Rocky Pastebin；此处可提供链接。
- 特别是对于负面结果，请留下您的 MM @handle，以便我们与您联系获取解决方案。
- 如果所报告的项目与 QA: Testcase 相关，请注明。如果它应该成为一个 QA: Testcase（即使目前不是要求），请建议标题并在 wiki 仓库中创建 issue，以便我们添加。

## UPSTREAM（上游问题）

- 当以特定顺序执行步骤时（配置网络 -> 禁用 kdump -> 选择某些 OS 安装组 -> 配置默认存储 -> 再次配置存储，但这次启用加密），Anaconda 出现错误，已通过多个 openQA 测试套件和 ESXi 上的手动安装确认 - RC1_2 中重新测试 - UPSTREAM - @lumarel
- 该问题在 RHEL8.6 上可复现 - @atomicturtle
- 已向 RH 报告问题 <https://bugzilla.redhat.com/show_bug.cgi?id=2085321> - @stack

## FAIL（失败）

- ESXi secureboot (x86_64) 仍然失败，但属于预期行为 - @lumarel

## NOTABUG（非缺陷）

- Minimal：选择具有不可用依赖项（aide 等）的 SCAP 配置文件，在安装过程中选择"忽略依赖项"会导致 Anaconda 在最终 OSCAP 检查时崩溃。NOTABUG，这属于文档记录 - @atomicturtle
- Minimal ISO：再次缺少 rsyslog 的源，且在安装时不知何故也未将其拉入，这意味着安装后缺少它（boot ISO 和 dvd1 ISO 不会出现此问题）- NOTABUG (per @label) - @lumarel
- Minimal ISO：如果使用 minimal iso 安装服务器基础环境并在安装后启用 cockpit，SELinux 子菜单显示错误 "semanage: command not found"（boot/dvd-iso 不会出现此问题）- 也标记为预期行为 - NOTABUG (per @label) - @lumarel
